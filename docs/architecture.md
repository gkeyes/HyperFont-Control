# 实现与覆盖边界

Go 核心负责读取字体元数据、导入、配置校验、生成字体表与生命周期管理。WebUI 通过固定 `hfctl` 入口传递 Base64 JSON，不把用户路径或字体名拼成 Shell 语句。设备不运行 HTTP 服务；`cmd/hfdev` 仅供本地夹具预览。

模块首次记录 ROM 原始字体表和内容哈希。每次提交生成独立 generation，保留用户源字体的轮廓及度量，按中文/拉丁用途处理覆盖字符集合，原系统的其他语言、表情、图标保留。Android 上提交前调用设备真实字体表解析器及 Font.Builder；非法 named family 属性等配置被拒绝。

HyperOS 多入口包括 system 主表、system_ext 的 HyperOS/MIUI 表、product 自定义与 MiSans 独立表。对于小米动态选择器，覆盖对应的物理表，避免把会变换的链接目标误认为系统被修改。自定义中文拥有优先的内部 named 入口，同时保留带语言标签的匿名回退族；named family 不保留 Android 不允许的语言属性。

开机时先完整校验 generation 和原始依赖，在 `/dev/hyperfont-control` 建立临时字体内容与目录视图。字体在 system/product 视图之间使用实际文件的硬链接，不以空占位文件加逐字体绑定实现。全部准备完成后再暴露目录和配置绑定；失败撤销本次挂载。模块不修改系统分区，也不向共享 OverlayFS 镜像写字体。

HyperOS 默认控件可能在请求系统字重前应用厂商换算。独立 Zygisk 兼容层仅在本模块自定义默认字体已就绪时，修改应用进程内相关字体兼容开关；不修改全局系统优化属性。未注入 Zygisk 的进程、私有绘字路径和应用自带字体需分别评估。

## 启动保护

暴露自定义字体前写入 `boot-attempt.json`，记录 boot ID 与 generation。`boot-completed.sh` 在 Android 完成开机后确认匹配的 mounted 记录；`service.sh` 为没有此回调的管理器提供有时限的等待与重试。二者不挂载字体，不重启设备。

下一次启动发现同一 generation 在另一 boot ID 中未确认，则记录 `guarded` 并使用系统字体。系统字体成功启动不会把那份失败配置标记为成功，因此不会在再下一次启动自动重试。重新提交生成新 ID，可以再次尝试；提交系统字体并重启会清除保护记录。升级安装器也会重建已提交配置，属于一次新的显式尝试。

此保护只能在下一次执行模块脚本时生效，不是当前卡死启动的即时救援，也无法判断未完成开机是否一定由字体导致。

## 数据与验证

持久数据位于 `/data/adb/hyperfont-control`：`library` 保存源字体，`uploads` 保存未完成上传，`generations` 保存配置与生成字体，`active`/`pending` 分别指向最近挂载和待生效配置。草稿独立保存。数据目录带归属标记；卸载只清理本模块拥有的目录。

上传自动清理以数据及元数据文件的最后活动时间为准，24 小时内正在传输的文件保留。显式清理只处理有效 token 的普通文件，不递归删除目录、不跟随符号链接，也不进入字体库。

`visible=true` 要求本次启动 mounted、字体表内容匹配、字体为非空普通文件且内容哈希匹配。一次检查中相同 inode 共用哈希结果；独立路径即使同名同大小，也各自验证。该状态不代表应用每个字形均来自选定字体。

应用私有字库、网页下载字体、游戏图集等不属于系统字体覆盖范围。字体家族自动合并与自动调整行距暂未实现。
